# 钢四参谋（hoi4_advisor）

让猫娘看懂你《钢铁雄心4》这局的局势，也能帮你发力所能及的加成。

定位是**参谋，不是外挂**：读侧只读存档，写侧只发白名单里的低风险命令，
部队调动、宣战、吞并这类会毁档的操作一律不接。全程不抢键盘鼠标，游戏不用切前台。

## 值钱的地方

存档里有 334 个国家的完整数据，游戏界面只给你看很少一部分。这个信息差就是参谋的价值：

- 盟友有 3 个师赖在你国土上（界面上要一个个点才看得到）
- 政治点堆到 2000 已经溢出，等于白攒
- 某州堆了 8 个师，补给多半跟不上
- 陆军经验 500 多了没花，够改一次编制

这些不是报数，是"你漏看了什么"。

## 用起来是什么样

跟猫娘说这些话就行：

- "我这局怎么样" / "看看我的存档"
- "我现在该干什么"
- "我部队都在哪"
- "有什么要注意的"

她会回一段带日期的简报，形如：

```
【钢四局势】1939年10月1日存档 · 卢森堡（LUX）
政治点 345.5 · 稳定 76% · 战支 10% · 人力 11.1万
民工 7 · 军工厂 4 · 船坞 0 · 研究槽 3
师 16 个（行军 10，缺编 12）

要注意：
! 战争支持只有 10，动员拉不动
· 指挥点 140，满值是 100，不花就是浪费
```

## 前置条件（一条）

1. **得先存过档**。局内状态只在保存时落盘，插件的眼睛只能看到"上次存档那一刻"。

**存档格式不用管**：**0.9.12 起二进制存档（HOI4bin）直接能读**，文本档也照读，
游戏用户目录 `settings.txt` 里的 `save_as_binary` 是 `yes` 还是 `no` 都无所谓——
便携版/绿色版默认存二进制，以前要改设置再重存一次才行，现在拿来直接读。
（插件自带一张从实档逆出来的 token→字段名表，把二进制的数字标签还原成
`manpower`/`stability` 这种字段名，读出来的树跟文本档一模一样，下游全都通用。
只有极少数"写坏的二进制残档"才会读不了，那种情况插件会如实报错并给出下一步。）

自动存档建议设成**每月一次**：游戏内一个月大约 2～5 分钟真实时间，
所以数据最多滞后一个月。这个精度对"参谋"够用，对"代打"不够。

## 她自己会找路径

不用配。启动后自动做三件事：

1. 找存档目录：**先看正在运行的游戏进程在哪个安装目录**（便携版/绿色版会把存档
   写在自己目录下的 `Paradox Interactive\Hearts of Iron IV\save games`，不在 Documents），
   再问注册表里 Documents 的真实位置（可能被重定向到别的盘），最后兜底几个常见位置。
2. 跨所有存档目录按修改时间挑**最新的那一份**（不是按目录顺序取第一个）——
   mtime 最新的就是"现在玩的这局"。**0.9.12 起二进制档直接能读**，所以最新档
   是二进制也照样解析出现状，不会退回旧文本档冒充；只有"写坏的二进制残档"才读不了，
   那种情况会如实报错、给出下一步，绝不拿旧档糊弄（0.9.11 起的规矩）。
3. 找游戏安装目录，可能有多份，会挑**版本和存档最接近的那份**。

第 3 条不是洁癖：省/州的编号在版本之间会重排。实测遇到过 1.13.1 的存档配 1.14.8 的数据，
中国的部队被标到"九州"。所以版本对不上时会明确告诉你"州名和部队位置可能不准"，
而不是装作没事。

### 想手动指定

改插件目录下的 `config.json`：

```json
{
  "save_dirs": ["D:/我的存档/Hearts of Iron IV"],
  "save_file": "",
  "game_dir": "D:/Steam/steamapps/common/Hearts of Iron IV"
}
```

`save_file` 填具体文件路径可以锁定某一份存档（比如你在同时开好几局）。

## 能动手的部分（写侧）

```
你说话 → 白名单校验 → 注入过的 DLL → PostMessage → 游戏控制台
                          ↓
                 记一条"发之前是多少"
                          ↓
              下次存档解析完 → 自动核对有没有到账
```

**能发**：政治点、人力、陆军经验、指挥点、燃料、稳定度、战争支持、
研究加速、瞬间建造、瞬间训练、国策自动完成、加民族精神。

**不发**：`moveunit` / `tp`（调部队）、宣战、吞并、切国家、读档存档。
理由不是"安全"，而是发错一次就要读档，而你很可能正在自己指挥同一支部队。

三条诚实约定：

1. **只承诺"投递"，不承诺"生效"**。控制台失败了游戏只在左上角飘一行红字，DLL 看不到。
2. **下次存档自动核对**。发之前记下那个数，存档解析完再比，告诉你"确实 +100"还是"没看到变化"。
3. **状态不同步时直说**。如果你中途手动按过 `` ` ``，命令可能全打空，核对会暴露这件事。

注入失败会分类给原因：游戏没开 / 权限不一致（游戏以管理员启动而 N.E.K.O 不是）/
DLL 缺失 / 端口被上一个实例占着，各给各的处理办法，不会只说一句"连不上"。

## 真的替你动手：国策和调兵（0.3.0 新增）

上面那条线走的是**控制台**，只能加数值。这两件事不一样，它们是**以玩家身份操作**，
跟在国策树里点一下、在地图上右键一样，存档正常记、成就正常给。

```
选国策：CCountry+0x14e8 -> CNationalFocusProgress
        把 +0x18 写成某个 CNationalFocus*，引擎下一 tick 自己推进、自己完成、自己解锁后续

调兵：  CCountry+0x2f8 是师列表，CArmy+0x38 是当前省
        按陆地邻接 BFS 算整条路线，再调引擎自己的下单函数 0xc12280(unit, &pathVec, replace, 2)
```

调兵那条**必须**调引擎函数，不能自己写路径容器：`CArmy+0x2a8` 不是"订单对象指针"，
是内联的 `{data, cap, size, alloc}`。手改 size 会让引擎读到空指针，实测崩过两次。
调 `0xc12280` 之后引擎自己扩容、自己 new 订单对象，才安全。

三条边界：

1. **国策只接受"当前可选列表"里的节点**（`+0x80` 那个 vec）。跳节点选国策等于作弊，
   后面树结构也会错乱。
2. **调兵只走陆地邻接**，不穿海、不瞬移；一次只动你**自己**的师。
3. **版本一变就只读**。偏移和函数 RVA 都是从 1.16.9 逆出来的，换个版本硬写就是存档报废。
   写之前会比对 exe 大小，对不上就只让看不让动。

还有一件必须说清楚的事：**写进 `+0x18` 之后，引擎会在下一次 tick 校验条件**
（前置、政治点、互斥）。不满足它会自己把这一条丢掉——跟你在国策树里点一个灰节点一个结果。
暂停状态下看不到这件事，所以下次问的时候会对账："你上次选的那个没留下来"。

## 划线和接管部队（0.4.0 新增）

调兵是一次性的。真打仗要的是**作战计划**：一条防线自己补位、一条进攻线自己往前推。
这件事不做就被"一次只能调几个师"卡住了，所以 0.4.0 加了两块。

### 游戏里按 F7 / F8（0.5.1 起半废；0.6.0 起默认停用，键让给「按住说话」）

```
F7  把鼠标指着的那个省里的师，交给 YUI 指挥（成功一声高音；失败两声低音）
F8  放回去
```

**现状（0.5.1）**：F7 的判据是"鼠标指着哪个省"，这要靠地图标定换算；而 0.5.0 之后
调兵划线全走进程内，再没有功能会做标定——所以 F7 目前固定走失败分支（两声低音，
并在接管表里留言）。**替代**：直接跟猫娘说「把柏林的部队交给你」，`hoi4_squad assign`
按地名接管，不碰鼠标。

**终局**：用户要的语义是"选中的部队给我"（选中一个集团军给一个集团军）。
静态逆向已定位 `CGameIdler + 0x508 = CSelectionList`（vtable 0x23EF1B8），
运行时验证后把判据换成读选中列表，F7/F8 就是完整形态。

按键在**游戏进程里**读（`neko_hoi4_agent.dll` 里的 `hotkey_thread`，`GetAsyncKeyState`
+ 前台窗口必须属于游戏进程）。为什么不在 mod 里做：HOI4 的 mod 脚本没有"按键触发效果"
这个接口。`interface/*.gui` 的 `buttonType` 能写 `shortcut = "z"`（作战计划那几个按钮就是
这么绑的），但那只对**游戏自己认识的按钮名**生效，我们自己加的按钮没有对应代码分支。

### 按住说话：说的话直接进聊天窗（0.9.0）

把猫娘聊天窗开在游戏边上，按住 F7 说一句，松开之后：

```
按住 F7 说话 → 松开 → 插件自己在本地识别成文字
                   → 聊天窗里长出「我：…」，就是你刚说的那句
                   → 她在同一个窗口回你，气泡和声音都有
```

**0.8.0 那条游戏内字幕已经去掉了**（`ptt_overlay` 默认 false）。当时的想法是
"不用切窗口"，可实际用法是把对话框开在游戏旁边——画面上再浮一条就是重复，
还挡视线。

怎么让文字进到对话框里，是 0.9.0 换的最要紧的一处。0.8.0 是插件自己连
`ws://…/ws/YUI` 发文字，实测两个毛病：

- 那条连接会**顶掉聊天窗的连接**（WS 里能看到 `CHARACTER_SWITCHING_TERMINAL`），
  开着对话框打游戏就变成反复断线重连；
- 后端**只把她的回复回给发起请求的那条连接**，聊天窗里永远看不到"我说的"。

现在改走宿主自己的"游戏路由" HTTP（`/api/game/hoi4/route/*`）：

```
route/start            声明游戏接管
route/voice-transcript 把识别出来的文字当成"用户说的话"塞进对话
                       → 后端广播 user_transcript → 聊天窗自己长出「我：…」
route/drain            取后端结果，result.line 就是她的回答
route/end              把输入还回聊天窗（一直挂着聊天框会以为被游戏占着）
game/hoi4/speak        让她把这句话念出来：TTS、气泡、音频全在宿主里
```

好处是插件既不碰音频也不碰 WS，音色和记忆跟平时聊天完全一样。`speak` 在
`route/end` 之后照样能播（实测过），所以每轮说完就把输入还回去，不长期占着。

### 用嘴下令：调兵 / 划线 / 查部队（0.9.0，0.9.1 修好调兵）

```
"把华沙的师调到柏林"           → 直接调兵
"从华沙派两个师去柏林"         → 带数量
"在柏林划一条防线" / "守住华沙" → 直接划线
"柏林附近有什么部队"           → 报敌我位置
```

认出来就**当场动手**，不等模型（模型来回三四秒，按住说话等不起）。
认不出来照旧当普通聊天。只认这三种，宁可漏认也不认错——「政治点调到 500」
这种要是被当成调兵，就是在替你乱动存档，所以资源、工厂、科研、稳定度这些词
直接排除，纯数字的目的地也不认。

**0.9.1 修的是「说了调兵她没动」**：语音调令以前跑在框架的临时事件循环上，
钩子一返回 loop 就关了，所以每条令都卡在"插件主循环没跑起来"。现在她有自己的
常驻循环；顺便把真实语音里的噪音（"我做以下部署…柏林所在省份博兰登堡的
一个散兵师…"）也解析对了，说州名算全州。

**还能点兵种**：说「把勃兰登堡的那个伞兵师调到柏林」，她会读每个师的编制名
（"空降伞兵师1941A型"），只动伞兵，不会像以前那样按列表顺序抓一个步兵走。

第一次调兵她会问一句「你这局玩的是哪国」（存档可能是上一局的），
答一句「德国」就行——同一条令会自动接着办完，之后这一局不再问。

> 如果她说"令已经写进去了"但部队看着没动，先看游戏是不是**暂停**着：
> 暂停时时间不走，任何部队都不会开拔。

### 看图标、查编制、盯前线（0.9.2 / 0.9.3 / 0.9.4 / 0.9.5 / 0.9.6 / 0.9.7）

**图标翻译**：游戏单位牌上的图标是按兵种画的，她以前只能看到"编制名"。
现在她会读编制（名字 + 编成），把图标翻译成话：

```
图标：坦克｜中型坦克师1940A型 —— 3 个师
    编成：摩托化步兵×6、轻型坦克×2、中型坦克×4、炮兵×1…
    在：克尔曼、阿巴斯港…
图标：伞兵｜空降伞兵师1938A型 —— 3 个师
```

说"坦克师/伞兵师/山地师"时按图标兵种挑，不会再抓错。

**查编制**：`hoi4_divisions`（"我有哪些兵种""这个坦克师是什么编成"）。

**前线**：`hoi4_frontline`（"前线怎么样""哪里在打""这块地归谁""谁在进攻"）——
**全部**交火地区（一处不落）、**每块地现在归谁控制、法理上属于谁**、
**攻方守方各是哪些国家、各投入几个师**、**我国和交火对手各控制多少省**。
另外也保留"省里有哪些师"这一栏。`action=context` 能拉到开局那份全量情报，
`action=notes` 是哨兵最近的通报。

```
塞内加尔（12834）：法国｜攻 英国 2 个师；守 法国 4 个师、意大利 1 个师
四川（1395）：日本（法理属中国）｜攻 中国 1 个师；守 日本 1 个师
波尔图（9817）：葡萄牙｜攻 英国 9 个师；守 葡萄牙 2 个师
```

**开局总览（0.9.4 改）**：游戏一进来，哨兵扫一遍全部陆战和**全服省份控制图**
（`CProvince+0x160`），把「全部交火地区 + 我国/敌对国各控制多少省 + 交火省里
法理属我但被占的」整理成**全量情报**交给模型，让她做一段汇报。
给模型的那份不截断；万一宿主 `chat` 端点不通，才降级成精简播报（前 8 处 +
"另外还有 N 处"），**降级会记日志和计数**，全量情报仍存在插件里随时能问出来。

**推进通报（0.9.4 改）**：每 30 秒对比一次全服控制图，**任何省**易主都报
「德国（我方）推进到了华沙（原属波兰）」——不只盯着交火省，所以交火结束后
才占下来的地也跑不掉；按新控制国标我方/敌方，一次最多逐条报 3 处，多的汇总。
交火开始/结束/增兵照旧报。

她只认你**亲口确认过**的国家（说一句「我玩的是德国」），
因为存档很可能是上一局的，自动认人会报错国家。

> **0.9.3 起控制者和战斗双方都是真读出来的**，不再是"拿驻军国猜"（偏移和验证
> 见开发文档 10.12）：`CProvince+0x160` 是控制国序号（`CCountry+0x18` 那个整数），
> `CState+0xD0` 是法理所有者，`CLandCombat+0x30/+0x38` 两个 `CLandCombatant`
> 里各有一份参战师数组，按 `CCountry+0x2F8` 的全师表反查国家。
> 读不出来的省会明说"控制者没读出来"，不会拿驻军国冒充。

按键独占（0.8.0 的成果）原样保留：

```
游戏在跑 → 插件抢注 F7 → 这个键从此只在插件手里
                       └→ 游戏收不到，不会变成指令
```

抢不到就**不干活**，绝不偷偷退回轮询——宁可按了没反应，也不能让按键漏进游戏。
正常情况下不会抢不到：游戏一开，宿主就先把 F2–F8 让出来了（下面闸门那段）。

- **识别在插件里做，不走宿主**。`asrlib/` 里带 sherpa-onnx 运行库，
  `data/models/paraformer-zh/` 里是 216 MB 的 Paraformer int8 模型，
  完全不联网、不调宿主的语音接口。1.7 秒的话识别只要 0.07 秒
- 游戏进程在跑就一直独占这个键（不看前台），切到桌面按同一个键也还是说话
- 送进对话框的是**文字**，记忆和音色都是同一个她

> 为什么不用宿主那套语音识别：用户实测"识别不好"。宿主走的是实时 VAD + 它自己的
> ASR，中文短句容易吞字；本地 paraformer 是整段识别，句子完整了再动，
> 加上模型就在本地，没有网络抖动。

**F7 / 空格键被抢的问题（0.7.0 让出宿主，0.8.0 才真正独占）**：宿主用 Electron 的 `globalShortcut`
占着 F2–F8（F7 聚焦聊天框、F8 隐藏全部界面），系统级抢占——按 F7 会把 YUI 窗口
拉到前台，之后你按空格暂停游戏就不再是游戏在收，这就是"空格暂停失效"的来源。

做法不是改键位，而是**游戏一开就让宿主把全部全局快捷键让出来**：

```
插件 gameguard.py（每 2 秒扫 hoi4.exe）
   → 写心跳 %APPDATA%\N.E.K.O\neko_game_guard.json（mtime 就是心跳）
   → 宿主里打进 hotkey-manager.js 的一小段补丁每 700ms 看一眼
   → 看到就 globalShortcut.unregisterAll()，游戏退出立刻注册回来
```

心跳 15 秒不更新就自动恢复——插件崩了、被禁用了，最坏情况热键只被关 15 秒，
不会把你的猫娘永久锁死。补丁是往 `resources/app.asar` 里打的，宿主升级会覆盖回原版，
那时 `hoi4_voice action=check` 会直接告诉你"补丁没打"。

想让键位永久归游戏（不依赖闸门）也可以说「把 F7 让出来」，走
`hoi4_voice action=fix_hotkeys` 把宿主的键位改成 `Ctrl+F7`/`Ctrl+F8`——
**改完要重启一次 N.E.K.O.**

想关掉：说「按住说话关了吧」（`hoi4_voice action=off`），或者改 `config.json` 的
`ptt_enabled`。换键位是 `ptt_key`，换麦克风是先 `hoi4_voice action=devices` 看编号，
再填 `ptt_mic_device`。不想让宿主让出热键就设 `game_guard_enabled: false`。

> 麦克风没声音的时候她会响两声低音并说"没听到声音"，不会白花一次模型调用。
> 排查先看插件目录的 `data/voice_log.jsonl`——每一轮都有一行：按了多久、录到多大声音、
> 本地识别出来什么（连带识别耗时）、她回了什么。
>

> `model.int8.onnx` 和 `tokens.txt` 放进 `data/models/paraformer-zh/` 就行，
> 用 `hoi4_voice action=check` 能看到它到底缺什么。

### 看某地附近的部队（0.5.1 新增）

`hoi4_units_near`：说国名（波兰）就以**那个国家的部队**为中心，说地名（柏林）就以那个省
为中心，往外扩几省邻接，把范围内**每个国家**各有多少师、驻在哪些省都列出来——
敌我都报，实时内存位置。实现上全是只读：`locate_named`（按国名找 CCountry，
**不写玩家缓存**，免得把波兰记成玩家国家去动人家部队）→ 遍历国家读 `(army, prov)` 轻量

核一遍，对不上的直接作废。

### 划线：直接改游戏里的前线对象（0.5.0 重写）

0.4.0 是"借玩家的手"——模拟按键 + 点地图。那一版能用，但有两个硬伤：要标定地图投影
（划一条线会把视角拉到最小缩放），而且会抢前台。0.5.0 换成了和调兵一样的做法：
**读写进程内对象 + 调引擎函数**，全程不碰鼠标键盘。

数据结构（1.16.9，逐个实测过）：

```
CCountry  + 0x180 -> CPdxArray<CTheatre*>     战区
CTheatre  + 0x58  -> CPdxArray<CFront*>       前线（10 条左右，cap 16）
CTheatre  + 0x70  -> CPdxArray<CArmy*>        归这个战区调度的师
CFront    + 0x20  -> CTheatre*                owner（构造时先写它，不然构造里解引用空指针）
CFront    + 0x28  -> CPdxArray<CProvince*>    这条线负责哪些省（cap@+0x30, size@+0x34）
CProvince + 0xAC  -> 省份 ID
```

三个引擎函数：

| 地址 | 签名 | 用途 |
|---|---|---|
| `0xC1F6D0` | `(country, provId) -> CProvince*` | 省 ID 换指针，**写之前必须用它换**，别自己猜地址 |
| `0xDDD0A0` | `bool CFront::BuildSections(this, int, bool)` | 改完省份重建线段，返回 true 才算接住 |
| `0xDD8E50` | `CFront::CFront(this)` | 建新前线时用；**先写 `+0x20` 的 owner 再 call** |

写省份时只覆盖数据、只改 `size`，**绝不动 `cap`**：P 社容器的 cap 手工改大，引擎下次
扩容时会踩到坏指针（调兵那篇里踩过两次）。省份数超过 cap 就截断并如实说出来。

实测结果（这台机器，德国开局）：读 10 条线全对；把第 9 条改成守柏林，`ok + rebuilt`，
一秒后引擎没覆盖；新建一条守 柏林+勃兰登堡，3 秒后还在，师数没变。

**为什么不改玩家手画的作战计划**：作战计划（`COrdersGroup` + `COrderInstance`）是"给某个
集团军下命令"，前提是玩家先在游戏里建了集团军。实测这台机器上玩家国家 **0 个集团军**、
1 个战区、10 条战区前线——所以只有战区前线这条路是通的。好处是不需要任何前置操作，
坏处是它管的是"这个战区守哪一段"，不是"这 5 个师沿这条箭头推"。

## 0.9.5：查前线 / 查编制卡住的两个原因

18:44 之后用户报「查询又出问题了」，插件日志里是
`__llm_tool__hoi4_frontline timed out after 30.0s` 和哨兵每轮
「找不到战斗管理器（CCombatManager）」。两件事是独立的。

**一、战斗管理器被海战否掉。** `CCombatManager+0x10` 装的是**所有战斗**，
`CLandCombat`（陆战）和 `CNavalCombat`（海战）混着放，顺序还会随战斗增删变。
旧代码只验第 0 个元素的 vtable 是不是陆战；这局 27 场里 7 场是海战，
第 0 个碰上海战就把整个管理器否掉，报出「偏移可能变了」这种误导结论。
下午验证时 17 场第 0 个恰好是陆战，所以一直没暴露。现在改成只验数组结构，
`_combats()` 里按 vtable 逐个挑陆战，海战不进交火列表（它也没有省份指针）。

**二、30 秒超时是两次白做的全服扫描。** 分段计时（真机 pid 20132）：

| 段 | 耗时 | 用不用得上 |
|---|---|---|
| `_locate_player` | 0.08s | 要 |
| `live.units()`（`_feed` 里） | 14.31s | **完全没用** |
| `units_by_prov()` | 15.20s | 只用来填「省内恰好有哪些师」 |
| `frontline()` 其余部分 | 4.25s | 要 |

`hoi4_frontline` / `hoi4_divisions` / `hoi4_units_near` / `hoi4_battle_plan`
都复用了调兵用的 `_feed()`，可它们一个都不用那份师列表。加上新版又串了一次
8 秒的全服控制图扫描，一次查询 37.98 秒，直接撞宿主每个 entry 的 30 秒看门狗。

改法：新增 `_player_only()`（只认人，不带师列表）给这四个工具；
`frontline(fast=True)` 让省内兵力只读缓存，控制图和攻守方照读；
`control_map(peek_only=True)` 让工具只吃缓存，扫描丢给后台线程
（`control_map_background()` + 独立 `_ctl_lock`，不跟工具抢锁）；
再加 `wait_for(20)` 主动收口，超时返回「先不报了」而不是让宿主砍掉整个调用。

真机回归：最坏情况（缓存全冷 + 后台扫描并发）17.10 秒，缓存热 1.02 秒，
四个工具全 `ok=True`；13 处陆战一处不落、0 个海战混入；离线自测 16 项全过。

## 0.9.6：她终于真的开口做汇报了

上一版留的唯一一项「宿主 chat 端点没验」，19:09 宿主开着时验了：**不通**。
日志里 `route/start` 明明成功，chat 却两次都回 `route_not_active`。

直接打宿主接口把原因挖出来了：

```
POST /api/game/hoi4/route/start
  -> state.session_id = "default"，game_route_active = true
POST /api/game/hoi4/chat  {"session_id":"default", ...}
  -> 1.3 秒返回 {"line":"三处交火，还乱得够呛……", ...}   通了
```

两个 bug 叠在一起：

1. `chat_event` 自造 `session_id = "hoi4_<时间戳>"`，跟 `route/start` 的
   `"default"` 对不上，后端判 `route_not_active`。
2. 成功响应是 `{"line": ..., "control": {}, "metrics": ...}`，**根本没有
   `ok` 字段**；旧代码 `not got.get("ok")` 会把已经生成的话也判成失败。

改法：`start()` 把返回的 `session_id` 存下来，`chat_event` 优先用它
（没有就 GET `/api/game/route/active` 拿，再兜底 `"default"`）；
成功与否改成**只看 `line`**。真机直调 `HostRoute.start() → chat_event()`
拿到「三处交火还叫事？一百个省都在手里了，别慌，先看看是哪三处再说。」
模型是 `deepseek-v4-flash`，1.3 秒。

所以开局那份全量情报现在会由她自己组织成 3～5 句汇报，而不是念一张表。
降级路径仍留着（失败写日志 + 连续 3 次升警告），只是不会再天天走了。

## 0.9.7：查询又超时，真凶是 DLL 的全局命令锁

11-09 20:32:50 `hoi4_frontline` 又被 30 秒看门狗砍了一次。0.9.5 已经把
工具里白做的全服扫描去掉了，所以这次不是工具自己的问题。

翻 DLL 源码看到 `client_thread` 里每条命令都包在 `g_cmd_lock` 里：

```c
EnterCriticalSection(&g_cmd_lock);
handle(line, resp, ...);        /* SCANALL 一条就扫全地址空间 */
LeaveCriticalSection(&g_cmd_lock);
```

也就是说**整个插件进程共用一个命令队列**。而后台哨兵每 30 秒一轮要做
`frontline()` 的 15 秒全服部队扫描 + `control_map()` 的 20 秒全服省份扫描，
加起来比间隔还长 —— 哨兵几乎永远占着队列，工具每条读都要排在几百条
命令后面。日志里控制图耗时从 5.5 秒一路涨到 19～27 秒就是这么来的。

另外还挖到两个叠加点：

- `control_map(peek_only=True)` 明明只读缓存，却要抢 `_ctl_lock`，而后台
  扫描正握着它 20 多秒。四元组赋值本身是原子的，这把锁纯属多余。
- 工具在 `peek_only` 落空时会顺手起一个 `control_map_background()`，
  等于自己又往队列里塞一份全服扫描。
- 工具异常 / 换局后，`_countries_cache`、`_units_by_prov_cache` 没按
  `(pid, base)` 失效，会拿上一局的 `CCountry*` 去读。

改法：工具入口打一个会自动过期的时间戳 `mark_tool()`，后台扫描在
「开始 / 取整段 / 收尾」几个点主动让位；哨兵在工具查询期间整轮跳过，
慢扫描改成**每 3 轮一次**（约 90 秒），控制图 TTL 提到 60 秒；工具只读
缓存、绝不自启扫描；`connect()` 发现 `(pid, base)` 变了就把所有地址缓存
一次清空。

顺着这条线又挖出三个叠加点：

- 模型每轮都把用户说过的「德国」填进 `country`，旧代码一见显式国名就
  跳过「已确认国家」快路径，去 `live.locate()` 全服扫 406 个 CCountry；
  存档里的玩家还是上一局的卢森堡，tag 校验把缓存也否了。现在**带国名
  也先比已确认国家**，真机 0.04 秒，而且 `_scan()` 改吃 180 秒国家表缓存。

### 一、先认局，再解析

## 0.9.11：读错存档 —— 便携版游戏 + 二进制档

用户反馈"存档读取还是有问题"。实测这台机器的真实故障是两层叠加：

1. **便携版（绿色版）游戏的存档不在 Documents**。1.16.9 那份装在
   `D:\Games\Hearts of Iron IV`，存档全写在自己目录下的
   `Paradox Interactive\Hearts of Iron IV\save games`。而 `detect_save_dirs`
   以前只扫 Documents（含注册表重定向）+ 盘根 PerfLogs，**根本没扫游戏安装目录**。
   结果插件一直读 Documents 里另一个 1.14.8 游戏 5 月留下的卢森堡文本档，
   拿半年前另一局的数据报"当前局势"。

   修法：`_detect_save_dirs_raw` 先取**正在运行的游戏进程的安装目录**
   （`save_meta.game_process_cached()`），把 `<安装目录>\Paradox Interactive\...\save games`
   排在候选最前，再拼上探测到的所有游戏目录、Documents 等。

2. **就算扫到了，也挑不对**。`find_best_save` 旧逻辑是"优先最新的*可读文本*档，
   二进制只当 fallback"。便携版默认 `save_as_binary=yes`，11 月的德国档全是二进制，
   于是永远输给 5 月的卢森堡文本档。

   修法：**mtime 最新的那份就是"现在玩的这局"，哪怕它读不了**。最新的档是二进制时
   照样返回它（让上层如实报"二进制读不了"），绝不退回旧文本档冒充现状；只有最新的档
   是"写坏的残档（非二进制）"时才退回最新的可读文本档。

配套：

- `resolve_paths` 多返回一个 `binary_blocker`（最新档是二进制时的详情 + userdir）。
- `save_meta.disable_binary_saves(userdir)`：把 `settings.txt` 的 `save_as_binary`
  改成 `no`（改前备份、先写临时文件再 replace、已经是 no 就不动）。
- watcher 自愈：检测到二进制档、**且游戏没在运行**时自动调用上面的函数改设置
  （游戏运行中改会被退出时覆盖，所以只在关掉后改）；受 `config.auto_text_saves`
  开关控制，每个 userdir 只改一次。
- `hoi4_situation` 拿到 `binary_blocker` 时，返回能照做的提示（"重开游戏、手动存一次"），
  而不是端出旧缓存；实时工具（前线/部队/编制）不受影响，照常可用。
- 读不了的档只在首次/换档时记一次日志，不再每 4 秒刷屏。

验证（游戏 pid 26092 运行中，全程只读文件、没碰游戏内存）：
`detect_save_dirs` 已含便携版目录且排第一；`find_best_save` 返回当前 GER 二进制档；
`binary_blocker` 正确；`hoi4_situation` 返回二进制提示而非 5 月卢森堡数据；
`disable_binary_saves` 六种 settings.txt 写法（含大小写/引号/空格/缺键）单测全过；
日志去重生效（重载后只记一次）。**待用户重开游戏存一次文本档后，复验完整解析链路。**

## 0.9.12：二进制存档直接读 —— 不用再改设置重存了

0.9.11 只是"如实报告二进制读不了 + 自愈改设置让你重存文本档"。这一版**真的把二进制档读出来了**，
便携版默认的 HOI4bin 拿来直接解析，`save_as_binary` 是 yes 还是 no 都无所谓，前置条件从两条砍到一条。

HOI4bin 的结构是 `HOI4bin` 魔数 + 一串"类型标签"磁带：字段名不是字符串，而是一个 16 位数字
（token），值前面标着自己的类型（整数/浮点/布尔/字符串/对象开合……）。难点全在两点：

1. **token→字段名**。数字标签本身没有含义，得有一张对照表才知道 `0x2883` 是 `stability`。
   做法是拿**同一局的文本档和二进制作对照**（文本档字段有名、二进制同位置是 token），
   两棵树并行遍历、在每个 (token, 名字) 上投票，跨版本错位产生的脏票用"类型闸门 + 全局一一匹配 +
   最少票数 + 强票冲突隔离"四层过滤清掉。最后落成一张 **803 条**的表（`hoi4_tokens.py`），
   覆盖率 91%，锚点字段（player/date/version/countries/states/manpower/stability…）全部人工核对过。
   拿不准的宁可留空（保持数字键），也不猜一个错名字进去。

2. **两种"定点数"编码**。Paradox 把带 3 位小数的定点数用了两套写法，都得还原：
   - **浮点标签里塞定点整数位**：`stability` 标着"浮点"，但原始位其实是整数 712（当成浮点是个
     非规格化的极小值 ~1e-42）。判据是"这个浮点值正不正常"——不正常就把原始位当整数 ÷1000 → 0.712。
     文本档对照 `stability=0.712` **逐字相符**。
   - **FIXED3 标签（0x0317/0x0318）存原始整数**：`manpower.ratio` 用的是这套，二进制原始值 331800，
     文本档也写 `ratio=331800`——所以这类**不除 1000，直接取原值**。（这个区别是关键：早先把 0x0317
     当成"没见过的标签"跳 0 字节，导致整个 ENG 国家对象提前闭合、字段全泄漏到上一层、中途错位；
     认出它是 4 字节定点后，三个测试档全部精确走到文件尾、404 个国家一个不少。）

日期是"从某纪元起的总小时数"，按无闰年历还原成 `1943.1.7.14` 这种和文本档一样的串。
读出来的树和文本档**同构**（字符串键、`__anon`/`__bare` 匿名块、日期同格式、布尔、
没认出来的 token 保留数字键），所以下游 `save_state`/`oob`/快照/简报全都不用改，直接通用。

性能：51–84 MB 的二进制档全量解析 6–14 秒；只读头部 8 KB 拿玩家国/日期/版本是瞬时的；

## 0.9.17：把守线的摆法做成和引擎一样

用户的要求很直接：**"把你的调兵逻辑实现得和引擎那种一样"**。那就先别猜，去数引擎
自己怎么摆兵——挑了几支正在执行计划的集团军，把每个师的位置、每省的本省敌师、邻省敌师
全数出来：

| 集团军 | 师数 | 接敌省 | 引擎实际分布 |
|---|---|---|---|
| 第9 | 17 | 2 | 1986→2、7982→15（本省敌 5 / 17） |
| 第16 | 18 | 4 | 1 / 5 / 3 / 9（本省敌 5 / 20 / 20 / 19） |
| 第5 | 22 | 5 | 1 / 2 / 1 / 1 / **17**（本省敌 5 / 20 / 17 / 5 / 20） |
| 第12 | 10 | 10（实占 10 省） | **每省正好 1 个**（本省敌从 1 到 7 都是 1） |

数出来的结论和我原先的假设**都不一样**：

1. **不是"每省 1~2 个"**。第5集团军 22 个师里 17 个堆在 12809 一个省。
2. **也不是"按威胁比例摊"**。第16集团军 5075 和 12809 本省敌都是 20，实际却是 5 和 3；
   第5集团军同样两个 20，实际是 2 和 17。
3. **每省保底 1 个是真的**。第12集团军 10 个省、10 个师，一个不多一个不少，
   而且不管那省本省敌是 1 个还是 7 个。
4. **实际分布掺了"战斗排队"**。HOI4 每场战斗有宽度上限，挤不进去的师在后方等——
   所以 17 个师堆在一省往上冲，不是分配算出来的，是战斗+补给+你手动操作沉淀下来的。

**所以引擎没有一条"分配公式"可以被反推。它是反应式的**：哪条线缺人就调最近的师过去，
正在打的地方持续补兵，打不下的地方按宽度排队。

0.9.17 就把这套反应式规则写进代码（`_quotas` + `dispatch`）：

1. **每个接敌省保底 1 个师**，师不够时先给"本省敌师多"的省——绝不空防；
2. **富余的师优先补"够打这个省还差几个"**（本省敌师数 +1 = 够打的量）；
3. **每省都够打了还有富余 → 全堆给本省敌师最多的那条线**（最激烈战线）；
4. **绝不从已经满足配额的省抽人**，避免来回搬兵；
5. **正在打的省的师抽不得**（引擎也不会把交火中的师调走，那叫临阵脱逃）；
6. 每轮只补缺口、一次最多动 2 个师，且**不重复下令**（师已经在去某省的路上就不再下令，
   否则 30 秒重置一次路线，师永远到不了）。

真机对照（同一支部队、同一份实时数据）：第9集团军我算 3/14，引擎实际 2/15；
第16 我算 1/6/6/5，引擎 1/5/3/9；第12 我算 8 省各 1（有 2 省各多 1），引擎 10 省各 1。
剩下的差异都来自那两处：**我的"线"是"接敌的省"（引擎的是你画的那条线）**，
以及**引擎会把兵堆在战斗宽度允许的地方**。

`auto` 现在跑的是：先守线（这套规则），线上不缺人才找弱点往前推。


崩在**代理 DLL 自己的线程**上，不在游戏主线程；而且是 `memchr` 起的头。指向 `SCAN` 命令。

**根因**（`dll/neko_hoi4_agent.c` 的 SCAN 分支）：

那个特征码扫描器小心地先 `VirtualQuery` 问一遍"这块内存读不读得动"，读不动的跳过，注释里写着"a blind memcmp loop would hit guard pages and kill the game"。
**但 `VirtualQuery` 只保证"问的那一刻"可读。** 游戏在结算战斗、移动师、读档时会把堆释放并重映射——
而整堆扫描要跑好几秒，这几秒里 `memchr` 正好扫到一块刚被游戏还回去的地址，就 AV 了。

**为什么这次才崩**：崩之前那几分钟正是最激烈的时候（10:56–10:59 日志里一片 `combat_start`/`combat_end`，
几十个师在登陆、增兵、撤退），堆变动最频繁。平时扫得快、赶上的概率低。

**修复**：不再直接对游戏堆做 `memchr`，改成每 1 MB 先 `ReadProcessMemory` 复制进自己的缓冲，再在缓冲里找。
`ReadProcessMemory` 碰到无效页只返回 FALSE，不会抛异常；游戏同时改这块内存也只会让我们读到撕裂数据、
少找一个特征，不会把游戏带走。

**验证**（`_p154`，构造了真机那个竞态——边扫边把这块内存反复分配/释放）：

| | 结果 |
|---|---|
| 旧 DLL | **`0xC0000005` 崩掉**，和真机同一个异常码 |
| 新 DLL | 400 轮扫描、内存被收放 63961 次，**全程存活** |

另外 `_p153` 确认功能没坏：新 DLL 在自己造的缓冲里照样找得到那个 8 字节特征，
扫未映射地址返回 `OK none` 而不是崩。

**教训已经写进铁律**：*不准直接对游戏内存跑 `memchr`/`memcmp` 这类可能越过边界的读——
`VirtualQuery` 的结论会过期，一律先复制到自己的缓冲里再碰。*

### 一、「注入失败」其实是我把扫描拖慢了

她的原话（聊天记录）：

**还加了一道必要的加固**：VEH 是**进程级**的，不认线程的话，扫描线程踩页会被 CALL 的
handler 接走，`longjmp` 回到主线程的栈上——那才是真灾难。现在两个 guard 都绑了线程 id。

## 0.10.0：世界资料库，以及「够得着」到底怎么判

这一版有两件事：**换 mod 不用改代码**（世界资料库），和**"这支部队走不走得到那个省"改成只看内存**。

### 一、世界资料库（atlas + 面板）

以前地图知识写死在一个按原版 `provinces.bmp` 生成的 `prov_px.json` 里。TFR 那种把整张地图、州划分、省份编号全换掉的 mod 一开，她说"去华沙"就落在毫不相干的地块上。

现在「一个世界 = 游戏版本 + 一组启用的 mod」，各自生成一份数据：

```
data/atlas/<world_id>/
  meta.json  provinces.json  states.json  countries.json  cities.json  adjacency.json
```

`atlas.py` 负责解析（按 `replace_path` 语义合并 mod 文件、扫 BMP、认州和国名、算邻接），`panel.py` 负责给引导界面供数据，`static/` 是四步引导页（找游戏 → 选世界 → 读取 → 完成）。换 mod 只是多一份数据，代码一行不用改。

实测：原版 1.16.9 → 13,375 省 / 1,016 州 / 301 国名 / 9,924 邻接，8~15 秒；TFR 1.0.6a → 14,973 / 1,444 / 562 / 11,500。原版邻接与旧快照**逐省零差异**，坐标抽样 300 省偏差 >30px 的 0 个。

### 二、「够得着」——先错在哪里

用户的原话：

> 地名解析没认出来，说是"够不着"。本喵跑了两轮，都说"够不着"，
> 连本来就让部队驻扎的省也不认，这不像地形的问题，像是插件那边读取邻接关系时出了毛病。

她猜的方向不对（邻接表是好的），但**报告完全正确**。真正的原因是三处叠加：

**1. 基准错了。** 旧代码判"够得着"只看**已接管部队脚下的邻省**。1939 德国铺波兰前线时，正面 34 个省里 27 个是德国自己的，但接管的第 4 集团军在南边斯洛伐克——于是 25 个省判"够不着"，**整条线一个兵都不摆**。部队走的是本国领土，基准应该是"我方控制的省"。

**2. 静默死锁。** `mine_all`（谁是自己人）只从 900 秒 TTL 的缓存取。缓存一冷它就是空的，于是"不是我的全算敌人"，每个有部队的省都被判成交火中，`free` 恒为空——**任何守线命令都下不出去**，而且不报错，只说"手上的师都在路上"。真机表现就是她反复说"先不动"。

**3. 路径穿中立国。** `find_path` 只按陆地邻接 BFS，不看省份归谁。实测 22 个师里 5 个的路线扎进**中立的波兰**，共 28 段，部队走到边境就卡住。

### 三、改法：判据全部走内存

用户明确要求：**存档一个月才写一次，控制权随占领随时变，不能拿存档判**。所以：

```
CProvince + 0x160  省的控制者（国家序号）
CCountry  + 0x18   我自己（国家序号）
```

两者相等就是这个省现在归我。**不需要"国家序号→国名"表**——那张表冷掉时会让判定整盘失效（上面第 2 条就是这个）。只比序号，一次读 `pcid`、每省一个 DWORD。

通行权四层规则（`make_passable`，全部读内存）：

| 序 | 判据 | 为什么 |
|---|---|---|
| 1 | 控制者 == 我自己 | 本国领土，随便走 |
| 2 | 控制者 == 部队此刻所在省的控制者 | 兵能站在人家家里，就说明那国对我们通行。否则驻在斯洛伐克的 12 个师连回德国的路都算不出来 |
| 3 | 控制者 == 目的地的控制者 | 能下令打进去的国，那个国家已经是交战国，穿过它是合法的 |
| 4 | 控制者 ∈ 交战国（warscope 认出来的） | 开战之后从本土去东普鲁士**必须横穿波兰走廊**；不认这条，东普鲁士永远"走不通" |

### 四、这次踩到的四个工程坑

**缓存必须跨调用。** `_fill` 会给每个目的地各调一次 `move_many`，各建闭包就等于把几千个省重读一遍——加了通行权检查之后 `hoi4_move` 直接 `TIMEOUT`（宿主 30 秒看门狗）。改成实例级缓存 + 60 秒 TTL，并**先用内存控制图批量预填**（哨兵已经整段读过同一个 `+0x160`，比逐省 CALL 快两个数量级），只有图里没有的省才逐省读。

**早退分支漏字段。** 接管状态因游戏重开失效时，`_fill` 走 `{"active": False}` 这条没有 `note` 的早退分支，上层 `res["note"]` 抛 `KeyError`，用户看到的是 `'note'`。改成 `res.get("note")` 并给一句能照做的提示。

**包装格式被当扁平表读。** `prov_to_state.json` 的真实结构是 `{"game_version": ..., "map": {...}}`，按扁平表读只会看到两个键、逐条转换全失败，整张 13k 条的表变空。（这段代码后来随"不用存档判控制"一起删掉了，坑记在这里。）

**把"没 tick"当成唯一解释。** 部队不动时我连续两轮判断"游戏暂停了"。真实情况是：**移动令确实在跑，只是慢**——一格要走几个游戏日。判据是看 `path` 有没有被引擎消费（`prov` 变了、`path` 空了 = 走完了），而不是看几十秒内有没有位移。

### 五、进攻波兰的完整链路

用户宣战之后，同一条调令就合法了：

```
下令：3550（东斯洛伐克，12 个师）→ 417（克拉科夫，波兰）
路线：3550 → 417                            共 2 个省

t=21s  战斗总数 28   417 无战斗
t=36s  战斗总数 29   417 攻=德国 守=波兰     ← 战斗生成
       前线工具：克拉科夫（417）｜攻 德国 12 个师；守 波兰 2 个师
```

打非我方领土时，工具会明确说一句：

> ⚠ 那个省现在不是你的领土（归 波兰）。命令进了引擎，但只有你已经对波兰
> 宣战时才会真的开进去；没宣战的话它会一直挂着不动——那不是命令丢了，是目标还不合法。

**注意边界**：代码只负责"命令下得对、下得出去"。**打不打得动、多久拿下，是战场结果，不属于代码的判断范围**——按照 0.9.18 定下的 M4' 铁律，战术结论归 YUI，代码只留眼睛、手和记分板。

## 0.10.1：她为什么只会「把师调到很远的省」

用户看完自己和她的聊天记录，报了四件事：

### 补上那只手：`action=advance`（推一格）

### 两个把原因说错的坑

**「还没认出跟谁在打」其实常常是版图空的。** 算前线要控制图，而控制图由版图哨兵每
~85 秒在后台重扫一次（一次 14~19 秒），**扫的时候会转身让给工具查询**，这一刻读到的
就是空。我第一版把空的原因一律写成"还没认出交战国"，把人往错的方向引。现在把两种
原因分开报：`no_enemy`（先把前线读一次就能解决）和 `map_cold`（等十几秒）。

**`asyncio.TimeoutError` 的 `str()` 是空串。** 超时被 `_agent_error` 原样透传，用户看到
的是一片空白（`display: ""`）。现在空消息兜一句能照做的提示。
